# Atlas

The chip's single source of truth: the architecture spec, its conformance to the RTL, simulation runs, waveforms and the process view, on one shared branch / run / cycle. Built from [`docs/plan.md`](docs/plan.md) (milestones M0–M6) and the B/A2/C1/C2 mockups.

```sh
npm install --legacy-peer-deps
npm run dev          # http://localhost:3100
npm run check        # typecheck + unit tests + production build
npm run test:e2e     # Playwright smoke tests (starts the dev server if needed)
npm run fixtures     # regenerate the sample extract and runs
```

## Views

| Route | What it shows |
|---|---|
| `/canvas` | The spec's layouts. Status on every block (dashed = not yet RTL-checked), port dots for spec-vs-RTL (● match, ◐ different, ○ missing), "RTL only" stubs, lenses, outline, drill-down, inspector with SV/Chisel sources. |
| `/spec` | Doc graph: block → interface → protocol → timing rule, with signal tables and each rule in words. |
| `/runs` | Run library, protocol checks (the spec's timing rules evaluated over `signals.json`), virtualized log, waveform strip. |
| `/process` | Pipeline stages from the spec's `process:` section, tokens from `transactions.json`, stalls from the handshake signals, follow-an-instruction, occupancy over the run. |
| `/workspace` | Canvas, process, log and waveform on the same cycle. |

Branch, run and cycle live in the URL (`?branch=…&run=…&cycle=…`) and are mirrored to other open tabs over a `BroadcastChannel`. ←/→ step one cycle, Shift+←/→ ten.

## Data

- **Spec:** `../architecture/soc.yaml` is read live (v1) and migrated in memory to v2 (`lib/spec/migrate.ts`): `maturity` → one `status` tag, ports and connections inherit the lower status of their endpoints. Set `ATLAS_REPO_ROOT` to read another checkout.
- **Sample branches** (`fixtures/branches.json`) are clearly marked "sample" in the UI:
  - `atlas/vector-dispatch-64b`: a v2 overlay (`fixtures/overlays/`) with statuses, RTL anchors, a decoupled protocol with timing rules, the `vcmd-64` interface and a process section; an RTL extract with one width mismatch, one missing port and one RTL-only port; runs 212 (drops a command at cycle 640) and 211 (passes).
  - `atlas/axi-burst-fix`: extract still pending in CI.
  - `atlas/empty-spec`: no spec on the branch.
- **RTL extract** `fixtures/rtl/<sha>/extract.json` (`atlas.rtl-extract/1`) and **runs** `fixtures/runs/<id>/{run.json,events.jsonl,signals.json,transactions.json}` are generated by `scripts/make-fixtures.mjs` from a small cycle model, so the log, signals and transactions agree with each other.

In M1/M3 the stores in `lib/rtl/store.ts` and `lib/runs/store.ts` switch from `fixtures/` to the bucket; the views do not change.

## Code map

- `lib/spec` — v1 schema and validation (from the portal), v2 types, migration and overlays, timing-rule parser.
- `lib/rtl` — spec port → RTL signal names, `compare()` producing `atlas.compare/1`.
- `lib/sim` — rule checker over `signals.json`, signal lookup, waveform grouping.
- `lib/server/context.ts` — one call per page: spec, compare report (cached per spec/extract pair), runs.
- `components/` — one folder per view; `canvas/use-camera.ts` pans and zooms by writing a single transform.

UI rules come from [`docs/ux-directions.md`](docs/ux-directions.md): only `transform` and `opacity` animate (150–200 ms, Out Quart), every view is built once and updated in place, and every view has skeleton, empty and inline error states.
