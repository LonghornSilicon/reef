# RTL Drop 0 for PD (sky130)

**Milestone:** 10/14 "baseline audit + RTL Drop 0 to PD". **Status:** v2 draft, 2026-10-10 (TCMs moved
from OpenRAM to SRAM22). **Node:** sky130 (`sky130_fd_sc_hd` + SRAM22 macros). **Baseline:** CoralNPU `M3-2026-04-27`
(`72d700e`), bundle sha256 `74d3bc7e…6f4ff4`. No Chisel or generated-SV edits: the sky130 parts
replace two vendored files through the filelist.

### Instance names PD will see

- SRAM macros: `g_bank[b].u_macro` inside each of the two `Sram` instances
  (`u_core/itcm/sram/sramModules_0`, `u_core/dtcm/sram/sramModules_0`). ITCM has `b` = 0 only,
  DTCM `b` = 0..3 (bank = `addr[10:9]`). Each macro holds the full 128-bit word.
- Clock gates: `u_core/rst_sync/icg/u_cg` (gates the core clock for 2 cycles after reset) and
  `u_core/cg/u_cg` (CSR clock-gate bit, WFI, interrupts, debug halt).

## Things the PD flow has to know

1. **SRAM22 read data launch on the rising edge** (clk -> dout about 7.2 ns at ss) and are held by
   the macro until the next read, so the macro -> core paths get a full cycle. At ss 20 ns the worst
   is ITCM -> fetch `pc_bits` at +0.029 ns (DC sized it to the clock; `results/synth_reef_top_sky130_sram22.md`).
2. **SRAM22 `dout` is weak** (Alan's one-pager): keep fetch and LSU logic next to the macros, or
   buffer at each macro. A register would add a cycle and break the 1-cycle TCM read.
3. **`rstb` is tied high** in the wrapper (the generated core gives the TCMs no reset); `ce`, `we`,
   `wmask`, `addr`, `din` are driven by the core. Power pins `vdd`/`vss` (`USE_POWER_PINS` in the
   model) need hookup. See `rtl/sram/README.md` before relying on power-up behavior.
4. **Read the filelist as one compilation unit.** fpnew uses macros from `registers.svh` without
   including it. In Yosys: `read_slang --single-unit`, and read both `.lib` files with
   `read_liberty -lib` first so the macro and ICG cells resolve (`scripts/synth_yosys.sh --node sky130`).
5. **Design Compiler only:** `rtl/reef/synth/edff_dc.sv` replaces `edff.sv` (an equivalent
   rewrite that avoids a DC VER-37 crash). `scripts/synth_dc.sh` does this; Yosys/OpenROAD flows
   use the filelist as is.
6. **Reset recovery:** the debug ndmreset register drives async resets in the RVV FMA unit. It
   meets at 20 ns but fails by 1.05 ns at 10 ns (PT); buffer that tree in P&R.
7. **Hold:** not checked before CTS. Pre-CTS runs show hold violations with ideal clocks
   (Drop 0 build, PT ss 20 ns: worst -0.67 ns, 20,713 reg->reg endpoints); these are for P&R to fix.
8. **max_transition:** the DC run at ss, 20 ns leaves ~19k max-transition violations for P&R
   buffering (`results/sta_m3_corners_sky130hd.md`).

(`docs/area-feasibility.md`).

## How to reproduce (ECE server)

```bash
export REEF_ROOT=$PWD LIB_DIR=/path/to/liberty OSS_CAD_SUITE=/path/to/oss-cad-suite
scripts/lint_reef.sh
NODE=sky130 scripts/run_reef_smoke.sh      # Verilator >= 5.032, riscv-none-elf-gcc >= 14
scripts/fetch_sram22.sh --gds                 # SRAM22 .lib (ss/tt/ff), LEF, GDS -> build/sram22/
scripts/synth_yosys.sh --lib sky130hd --top reef_top --node sky130
scripts/synth_dc.sh --top reef_top --node sky130 --period 20 \
  --db sky130_fd_sc_hd__ss_100C_1v60.db --sram-db sram22_512x128m4w8_ss_100C_1v60.db   # .lib -> .db with lc_shell
SIM=verilator MODELS="sram22 cycle" scripts/run_sram_sky130_tb.sh
SKY130_SRAM_MACROS=<pdk>/sky130A/libs.ref/sky130_sram_macros scripts/run_sram_sky130_tb.sh   # VCS, all models
SKY130_FD_SC_HD=<pdk>/sky130A/libs.ref/sky130_fd_sc_hd scripts/run_clock_gate_sky130_tb.sh    # VCS
```
