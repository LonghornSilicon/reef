# Scalar-core timing suite (RvvCoreMiniAxi, CoralNPU M3)

Microbenchmarks that measure the cycle timing of the **scalar core** of `RvvCoreMiniAxi` at the CoralNPU
**M3 release** (`google-coral/coralnpu` tag `M3-2026-04-27`, commit `72d700e`): fetch, dispatch, every
execution unit, write-back and retire, for 31 instruction classes. They run as cocotb tests on the
upstream Verilator model. A traced run plus a VCD scan produces `deliverable/timing.json`, the source of the
timing diagram: https://claude.ai/artifact/UTUJoms6cTLKvuNNvrUVNs

Each bench has expected cycle counts derived from the RTL source (file:line in `bench/scalar_timing_test.py`,
`SPRINT_SPECS`). Where the sim disagreed with the source, the sim wins: the expectation is marked
sim-calibrated and the reason is in `notes/discrepancies.md` (D1-D8).

## Layout

| Path | What |
|---|---|
| `bench/` | Bench sources (`b1_branch.cc` … `b10_system.cc`, `dep_chain.cc`, `fetch_ipc.cc`, `trace.cc`, harness `st_common.h`), the cocotb test (`scalar_timing_test.py`), `BUILD`, and the helper scripts below |
| `bench/sync.sh` | Copies the benches into `$CORALNPU/tests/cocotb/scalar_timing/` (the only place it writes in the CoralNPU tree) |
| `bench/waves.sh` | Runs traced versions and copies each VCD to `$WAVES` |
| `bench/collect.py` | Collects the bench JSON, scans the trace VCD, writes `results/` and `deliverable/timing.json` |
| `bench/make_review_packet.py`, `bench/make_diagram.py` | Regenerate the review packet and the diagram page |
| `bench/vcdpeek.py` | Prints parameters or per-cycle signal values from a VCD in the terminal |
| `bench/d4_repro/pipe_regs_check.sv` | Two-file check of the fpnew `PipeRegs` issue (D4) |
| `deliverable/` | `timing.json` (diagram source), `summary.md` (verdicts against the draft diagrams), `review_packet.md` (R1-R9, with the hand sign-offs) |
| `checklist.md` | Every claim checked, with source file:line, evidence and verification level |
| `notes/` | `discrepancies.md` (where source and sim disagreed, and why) and GTKWave layouts for R1-R9 |
| `results/` | Regenerated by `collect.py` (not committed), except `results/json/d4exp_*.json` (see D4 below) |

## Prerequisites

- A CoralNPU checkout at the M3 tag. No changes to it are needed; `sync.sh` only adds `tests/cocotb/scalar_timing/`.
  ```bash
  git clone https://github.com/google-coral/coralnpu.git && git -C coralnpu checkout M3-2026-04-27
  ```
- Bazelisk (it reads `.bazelversion`: Bazel 7.4.1), clang as the host compiler, `zip`, `liblz4-dev`, and Python 3
  (the helper scripts use the standard library only; the sim brings its own Python through Bazel).
  On Ubuntu: `sudo apt install clang zip liblz4-dev`.
- `zip` matters: without it every bench reports FAILED even when cocotb passed, because the test wrapper zips the
  JSON outputs.
- Tested on Ubuntu 22.04 (WSL2). Expect ~15 min for the first build, ~15 s for a warm re-run.

## Run everything

From this folder (`hw/tests/scalar_timing/`):

```bash
export CORALNPU=/path/to/coralnpu CC=/usr/bin/clang CXX=/usr/bin/clang++
bash bench/sync.sh && (cd "$CORALNPU" && bazel test --nocache_test_results //tests/cocotb/scalar_timing:all)
```

Expected: `Executed 17 out of 17 tests: 17 tests pass.` Keep `--nocache_test_results`: without it a second run can
report cached passes without running anything.

**What a pass means.** Each target compares measured cycles against its expectation. Most expectations come from the
source; the sim-calibrated ones are marked in the JSON and in `results/*.md` with the discrepancy that explains them.
So 17/17 shows the numbers reproduce; the `source-only` column in each `results/*.md` is the cross-check against the RTL.

## Numbers, waveforms and the deliverables

```bash
export WAVES=/path/for/vcds            # default ~/LHS/scalar-timing-waves; VCDs are 25-55 MB, never commit them
bash bench/waves.sh trace              # traced run of the TRACE bench -> $WAVES/trace.vcd
python3 bench/collect.py               # results/*.md, results/json/, deliverable/timing.json
python3 bench/make_review_packet.py    # deliverable/review_packet.md + notes/r*.gtkw (keeps existing sign-offs)
python3 bench/make_diagram.py --out /tmp/reef-scalar-timing.html
```

If the run reproduces, `git diff deliverable/timing.json` is empty. Per-bench logs are in
`$CORALNPU/bazel-testlogs/tests/cocotb/scalar_timing/scalar_timing_cocotb_<bench>/test.log` (search for `measured /`).

Waveforms for any bench: `bash bench/waves.sh <bench> [<bench> ...]`, then
`gtkwave $WAVES/<bench>.vcd -a notes/<layout>.gtkw`, or in a terminal:
`python3 bench/vcdpeek.py cycles $WAVES/trace.vcd <start_ns> <end_ns> core.score.dispatch.io_inst_0_ready ...`.
One cycle is 1.25 ns; signal paths are below `RvvCoreMiniAxi.`, e.g. `core.score.lsu.io_dbus_valid`.

## Verification levels

Every claim in `checklist.md`, `timing.json` and `summary.md` has one level: `human` (checked by hand in the
waveform, review packet R1-R9 and fetch row 1.5), `sim+wave` (cycle counts plus a scripted VCD check), `sim`
(cycle counts only) or `src` (read from source). `collect.py` marks a class `human` only while its review-packet
item reads `[x] agree`.

## Known caveat: the Verilator FPU (D4)

The M3 Verilator model builds the scalar FP32 FMA with **0** pipeline registers: CoralNPU passes fpnew
`PipeRegs: '{default: 'd3}` (a packed array), and Verilator puts the 3 only in the last format's slot. The
synthesized Drop 0 netlists have all 3 stages (DC and Yosys-slang). So in this sim, `fadd`/`fmul`/`fmadd`/`feq`/
`fcvt` run at 1 per 2 cycles with write-back at D+1; the hardware does D+4 and 1 per 5. The B5 expectations are
calibrated to the sim. The hardware numbers were measured on a rebuild with `PipeRegs` written row by row and are
kept in `results/json/d4exp_*.json`, which `collect.py` reads into `timing.json` (`source_intent_if_different`).
Once the `PipeRegs` fix lands in Reef, B5 should be re-run and its calibration dropped. `bench/d4_repro/` shows the
difference between tools in two files.

## Other notes

- `rdcycle` is not implemented on this core (it traps); the benches time with `csrr mcycle`.
- ITCM is 8 KB. `b1_branch` uses 8128 B; shrink a bench before adding cases.
- The cross-compiler is GCC from Bazel: use `#pragma GCC unroll 1`, not `#pragma clang`.
- `--trace-fst` trips a Verilator assertion; the traced model writes VCD.
